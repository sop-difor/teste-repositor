# E0 — Backup (rode você mesmo)

Objetivo: salvar **3 arquivos CSV** (um por tabela: `sinapi_itens`, `orse_itens`,
`seinfra_itens`) **fora do banco**, antes de qualquer mudança. Não altera nada no Supabase.

## Passo a passo

### 1. Pegar a string de conexão do banco

1. Abra o **Supabase Dashboard** → projeto **SOP.DIFOR**.
2. Menu **Project Settings** (engrenagem) → **Database**.
3. Seção **Connection string** → aba **URI**.
4. Escolha o modo **Session** (porta **5432**). Copie a URI. Ela tem o formato:
   ```
   postgresql://postgres.qexdnxqmiaarzwwwrcor:[YOUR-PASSWORD]@aws-0-sa-east-1.pooler.supabase.com:5432/postgres
   ```
5. Troque `[YOUR-PASSWORD]` pela senha do banco (a mesma seção tem o botão para
   revelar / redefinir a senha, em **Database password**).

### 2. Guardar a string num arquivo

Nesta mesma pasta (`gecope/sql/reestruturacao_tabelas`), crie um arquivo chamado
exatamente **`db-url.local`** e cole **só a string de conexão** dentro dele (uma linha,
sem aspas), já com a senha no lugar de `[YOUR-PASSWORD]`. Salve.

Esse arquivo é ignorado pelo Git (não vai para o repositório). Apague-o quando terminar.

### 3. Instalar dependências e rodar

Abra o terminal **nesta pasta** e rode as duas linhas:

```bash
npm install
node E0_backup.mjs
```

Funciona igual em PowerShell, Git Bash ou CMD — não precisa definir variável de ambiente.

> Se a senha tiver caracteres especiais (`@ : / ? # !`), o mais simples é redefinir a
> senha para uma só com letras e números na tela **Database password** e refazer a string.

### 4. Conferir

O script imprime, para cada tabela, o número de linhas exportadas. Compare com o esperado:

| Tabela | Linhas esperadas (2026-09-01) |
|---|---:|
| `sinapi_itens` | 263.586 |
| `orse_itens` | 176.367 |
| `seinfra_itens` | 58.510 |

(Se você tiver subido alguma referência nova desde então, os números serão maiores — o
que importa é o script terminar com "Concluído." sem falhas.)

Os arquivos ficam em `gecope/sql/reestruturacao_tabelas/backup/`:

- `sinapi_itens_AAAA-MM-DD.csv`
- `orse_itens_AAAA-MM-DD.csv`
- `seinfra_itens_AAAA-MM-DD.csv`

O script já **confere sozinho** que o número de linhas gravadas em cada CSV bate com o
`count(*)` da tabela — se algum arquivo sair incompleto, ele termina com `FALHA` e avisa
para **não usar** aquele backup. A conexão é sempre por TLS (`sslmode=require`), então a
senha não trafega em texto puro.

### 5. Guardar

**Copie a pasta `backup/` para fora do projeto** (Google Drive, HD externo, etc.).
Ela está no `.gitignore` — não vai para o Git de propósito (arquivos grandes).

Quando os 3 CSVs estiverem guardados e conferidos, me avise para seguir para a **E1**.

## Como restaurar a partir do CSV (se precisar)

Rodar no SQL Editor do Supabase **não** funciona para `COPY ... FROM` de arquivo local.
Use `psql` (ou o mesmo tipo de script Node) apontando para o CSV. Postgres 17:

```sql
-- esvazia a tabela alvo antes (cuidado!)
TRUNCATE public.sinapi_itens;
-- HEADER match: casa as colunas pelo nome do cabeçalho, não pela ordem
\copy public.sinapi_itens FROM 'sinapi_itens_AAAA-MM-DD.csv' WITH (FORMAT csv, HEADER match)
```

A coluna `id` é `GENERATED BY DEFAULT AS IDENTITY` — ela aceita os valores que vêm no CSV
sem precisar de `OVERRIDING`. Depois de restaurar, reajuste a sequência:

```sql
SELECT setval(pg_get_serial_sequence('public.sinapi_itens','id'),
              (SELECT max(id) FROM public.sinapi_itens));
```

**Este procedimento de restauração precisa ser testado uma vez** (restaurando para um
schema de rascunho) antes da etapa E6 — está previsto no plano.
